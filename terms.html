1. The Service

The Service is two products, Klaussy Review and Klaussy Loop.

Klaussy Review reviews pull and merge requests in the repositories you choose across GitHub, GitLab, Bitbucket and Azure DevOps. When a review runs, the Service downloads the pull request's code, runs an AI agent against it using the AI provider and credential you set up, and posts the result back to the pull request as comments and a check.

Klaussy Loop is a hosted agent that works on issues in your repositories. Section 2 covers it.

We may change, add or remove features over time. If we remove something material to a paid plan, we'll tell you in advance where we reasonably can.

2. Klaussy Loop

Klaussy Loop takes an issue (a work item on Azure DevOps) in a GitHub, GitLab, Bitbucket or Azure DevOps repository you've connected and plans the change. A person on your side approves the plan. Then Loop writes the code on a branch, runs your repository's tests and runs a QA step, which takes screenshots and screen recordings of your app plus its terminal output for an AI QA judge to review. After that it opens a pull or merge request and answers review comments on it.

  • Loop never merges. Reviewing what it produces and deciding whether to merge it is up to you, and you're responsible for the code you ship.
  • Loop acts in your repository with the permissions you grant it through your forge connection, and does only what those permissions allow.
  • Loop uses the repository variables and secrets you set in Loop settings, only for the run that needs them. You're responsible for what you put there.
  • If you turn on MCP servers, Loop can send them data and act through them during a run. Their own terms apply.
  • For iOS and Android apps, QA may run in disposable macOS virtual machines on hardware Klaussy operates, or in Android emulators on Google Cloud. They're deleted after each job.
