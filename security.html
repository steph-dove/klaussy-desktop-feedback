Security

Klaussy Desktop · Klaussy Loop · klaussy review · klaussy-agents

Reporting a vulnerability

Email stephanie@klaussy.com with "security" in the subject line. Tell us which product is affected (Klaussy Desktop, Klaussy Loop, klaussy review, or klaussy-agents), what you found, how to reproduce it, and what you think the impact is.

Please don't open a public GitHub issue or share details publicly until we've had a chance to fix it.

What we commit to

  • We'll acknowledge your report.
  • We'll keep you updated as we look into it and fix it.
  • We'll credit you for the find if you want us to.

How Klaussy Loop & klaussy review protect your code

  • Each review or Loop task runs in its own isolated, single-use container or sandbox with no public IP address.
  • Outbound traffic can only go through a proxy with an allowlist.
  • DNS requests go through a DNS firewall.
  • Your AI credential is held outside the agent by a proxy. The agent only ever sees a placeholder.
  • Stored credentials are encrypted with AWS KMS.
  • Forge tokens are scoped strictly to the repositories you authorize.
  • Only account owners and organization admins can change settings.
  • klaussy review posts reviews as comments, never as approvals; Klaussy Loop opens pull or merge requests after plan approval and never merges them.

How Klaussy Desktop & klaussy-agents protect your code

  • Local execution: Klaussy Desktop (SUL 1.0) and klaussy-agents (FSL-1.1-MIT) run locally on your machine with no Klaussy backend server.
  • Source-available & inspectable: Both repositories are source-available so you can audit every command, hook, and IPC bridge.
  • Optional container sandboxing: Desktop tabs can run inside isolated Nemesis8 Docker sandboxes to keep agent execution off your host.
  • Signed releases: Desktop builds for macOS and Windows are code-signed and notarized.

For what we store and how long we keep it, see the privacy policy.
